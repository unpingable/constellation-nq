## 2. Real cross-UID AF_UNIX behavior

Status: **blocked before execution**.

This sandbox refuses AF_UNIX socket creation with `EPERM`. It also prevents a
real local UID/GID transition: user namespaces and `setresuid` are unavailable
under the active `no_new_privileges` boundary. Existing unit tests that skip
when these privileges are unavailable were not counted as evidence.

The Noble guest harness has no cross-UID skip path and requires different
`nq` and `nq-helper` UIDs/GIDs plus a successful persistent-helper test,
admission, doctor, and collection. It also requires a new admitted report after
service start, restart, a second start, and reboot before writing
`AF_UNIX_CROSS_UID=pass`. That marker has not been produced.

The current guest harness does not yet independently exercise every requested
API-client subcase. These are exact open gaps, not inferred passes:

- an allowed client and a separately unauthorized client against the public
  daemon socket;
- peer-credential refusal details for the unauthorized identity;
- forced stale-socket crash recovery;
- forced helper disconnect/restart independently of a daemon restart;
- socket-path symlink and path-substitution attacks.

## 5. Crash and partial-write safety

Status: **passed locally within the injected failure boundary**.

[`build-release-bundle.sh`](../scripts/build-release-bundle.sh) now serializes
builders with an output-directory inode lock, builds in a hidden same-filesystem
publish directory, re-verifies staged assets, fsyncs outputs, invalidates and
fsyncs any old bundle marker before replacing public names, publishes each
artifact by atomic rename, and renames `SHA256SUMS` last as the new bundle
commit marker.

[`test_release_failure_atomicity.sh`](../scripts/test_release_failure_atomicity.sh)
executed these cases:

```text
concurrent lock refusal: nonzero (recorded status 1)
injected dpkg-deb failure: status 97, existing committed bundle unchanged
SIGKILL after two renames, immediately before the third: status 137, no SHA256SUMS
result: pass
```

The ordinary pre-publication failure preserves an existing committed bundle
byte for byte. The kill case may expose a completely written tarball and its
sidecar, but it cannot retain the old bundle marker or expose the new one.
Abrupt process death can leave a hidden
`.nq-release-publish.*` directory; it is distinguishable from a committed
bundle and must be removed only after confirming no builder holds the lock.

The injected cases do not constitute exhaustive power-loss, filesystem,
kernel, or storage-controller fault testing.
